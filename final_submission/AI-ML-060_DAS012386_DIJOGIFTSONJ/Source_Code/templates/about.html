System Methodology & Mathematical Framework

Theoretical foundation, chemical sensor mechanics, leakage-free cross-validation guarantees, and regularized objective functions of AI-ML-060.

1. Problem Formulation & Target Construction

Carbon monoxide (CO) is a colorless, odorless, and highly toxic air pollutant emitted primarily from incomplete combustion in vehicular engines and industrial processes. While certified reference analyzers (such as non-dispersive infrared photometers) provide gold-standard concentration measurements, they are bulky, expensive, and impractical for dense spatial deployments. Low-cost metal-oxide semiconductor (MOS) chemical sensors offer an economical alternative but suffer from cross-sensitivity to relative humidity, temperature, and interfering gaseous compounds.

In this investigation, we formulate an intelligent binary early-warning detection model to classify whether ambient carbon monoxide exceeds the hazardous concentration threshold of 4.0 mg/m³:

co_high = 1   if   CO(GT) > 4.0 mg/m³   else   0

Leakage-Free Rule: The continuous target CO(GT) is strictly excised from all predictor feature vectors $X$, preventing direct mathematical target leakage into the estimator.

2. Domain Feature Engineering & Safe Division

Chemical sensor responses interact strongly with ambient meteorological parameters. We engineer domain features using safe division with machine epsilon ($\epsilon = 10^{-6}$):

  • Sensor Ratio: $\text{co\_nox\_ratio} = \frac{\text{PT08.S1(CO)}}{\text{PT08.S3(NOx)} + \epsilon}$ (Captures carbonaceous versus nitrogenous vehicular combustion proportion using non-target sensor arrays).
  • Thermal-Moisture Ratio: $\text{temp\_humidity\_ratio} = \frac{T}{\text{RH} + \epsilon}$
  • Vapor Interaction: $\text{temp\_humidity\_product} = T \times \text{RH}$
  • Cyclic Temporal Indices: $\text{hour} \in [0, 23]$, $\text{month} \in [1, 12]$, $\text{day\_of\_week} \in [0, 6]$ extracted from the verified timestamp.
3. Leak-Free Preprocessing & Resampling Protocol

Severe class imbalance (10.58% high-CO minority class) can cause linear classifiers to collapse toward the majority class. However, standard naive implementations often apply SMOTE across the full dataset before splitting, which artificially leaks validation samples into training.

Our architecture enforces strict leakage prevention using imblearn.pipeline.Pipeline:

  1. Stratified 80:20 Split: Fixed seed (42), partitioning the dataset prior to computing any data-dependent statistics.
  2. Median Imputation: Replaces missing sensor readings (where -200 errors occurred) using median values fitted exclusively on training folds.
  3. Train-Fitted IQR Clipping: Clips outliers within $[Q_1 - 2.5 \times \text{IQR}, Q_3 + 2.5 \times \text{IQR}]$ learned strictly on training splits.
  4. StandardScaler: Standardizes features to zero mean and unit variance.
  5. In-Fold SMOTE: Generates synthetic minority samples strictly inside the training split of each cross-validation fold:
    $x_{\text{synthetic}} = x_i + \lambda (x_{\text{zi}} - x_i), \quad \lambda \sim U(0, 1)$
4. Regularization Framework (L1 vs L2)
Model A: L1 Lasso-Style Regularization

Penalizes the $\ell_1$-norm of the coefficient vector: $\lambda \|w\|_1$.

Forces uninformative or collinear sensor coefficients to exactly zero, acting as automatic feature selection. Solver: liblinear, $C=100.0$ (inverse regularization approximation to $\alpha=0.01$).

Model B: L2 Ridge-Style Regularization

Penalizes the squared $\ell_2$-norm: $\frac{\lambda}{2} \|w\|_2^2$.

Shrinks correlated sensor coefficients proportionally toward zero without forcing complete sparsity, stabilizing estimation under multicollinearity. Solver: lbfgs, $C=1.0$ (inverse regularization approximation to $\alpha=1.0$).
